# Internacionalização (i18n)

## Configuração

- **Locale padrão**: `pt-BR` (sem prefixo na URL)
- **Locale secundário**: `en` (prefixo `/en/`)
- **Estratégia**: `prefix_except_default`
- **Arquivos de tradução**: `i18n/locales/pt-BR.json`, `i18n/locales/en.json` (carregamento lazy)
- **`langDir`**: `'locales'` → os arquivos lidos pelo intlify estão em `i18n/locales/`. Os arquivos em `i18n/*.json` (raiz) são ignorados em runtime — **não editar esses, editar sempre os de `locales/`**

## Uso em Componentes

```vue
<script setup lang="ts">
const { t, locale } = useI18n()
</script>

<template>
  <button>{{ t('common.save') }}</button>
  <p>{{ t('patients.title') }}</p>
</template>
```

## Navegação com Locale

Sempre usar `useLocalePath()` para gerar URLs:

```typescript
const localePath = useLocalePath()

// Redirecionar com locale correto
navigateTo(localePath('/pacientes'))

// Link em template
<NuxtLink :to="localePath('/agendamentos')">Agendamentos</NuxtLink>
```

## Datas e Números

Usar `useI18n()` para formatar datas e números respeitando o locale:

```typescript
const { d, n } = useI18n()

d(new Date(), 'short')      // "29/03/2026" (pt-BR) | "3/29/2026" (en)
n(1234.56, 'currency')      // "R$ 1.234,56" (pt-BR) | "$1,234.56" (en)
```

## Adicionando uma Chave de Tradução

1. Adicionar a chave em `i18n/locales/pt-BR.json` (pt-BR é a fonte da verdade)
2. Adicionar chave equivalente em `i18n/locales/en.json`
3. **Nunca** hardcodar texto visível ao usuário nos templates

> ⚠️ Os arquivos `i18n/pt-BR.json` e `i18n/en.json` (raiz, sem `locales/`) são cópias de referência — **não são lidos pelo runtime**. Sempre edite os arquivos dentro de `i18n/locales/`.

## Checklist para Nova Tela / Novo Componente

Ao criar ou atualizar qualquer tela ou componente com texto visível ao usuário:

1. **Identificar** todos os textos visíveis no template (labels, placeholders, títulos, botões, mensagens)
2. **Criar as chaves** em `i18n/locales/pt-BR.json` sob o namespace da tela:
   - Landing page → `landing.<secao>.<chave>`
   - Telas SaaS → `saas.<tela>.<chave>` (quando i18n for conectado; por ora mock é string direta)
   - Áreas globais → `common.<chave>`
3. **Criar as chaves equivalentes** em `i18n/locales/en.json` com a tradução em inglês
4. **Referenciar** com `t('namespace.chave')` no template — nunca string literal

> ⚠️ **Armadilha conhecida:** Existem arquivos `i18n/pt-BR.json` e `i18n/en.json` na **raiz** de `i18n/`. Esses arquivos são **completamente ignorados** pelo runtime — o `@nuxtjs/i18n` lê apenas `i18n/locales/`. Editar os arquivos raiz não tem efeito nenhum e vai fazer os textos aparecerem como chave bruta (ex: `landing.hero.titleA`).

```
✅ Editar sempre:   i18n/locales/pt-BR.json   i18n/locales/en.json
❌ Nunca editar:    i18n/pt-BR.json            i18n/en.json  (ignorados)
```

## Adicionando um Novo Idioma

1. Criar `i18n/locales/<code>.json` com todas as chaves de `i18n/locales/pt-BR.json`
2. Adicionar entrada ao array `i18n.locales` em `nuxt.config.ts`
3. Atualizar seletor de idioma no header
4. Atualizar este arquivo

## SEO Multilíngue

O `@nuxtjs/i18n` injeta automaticamente `<link rel="alternate" hreflang>` nas páginas.
Usar `useSeoMeta()` com `useI18n()` para títulos e descrições localizadas:

```typescript
const { t } = useI18n()
useSeoMeta({ title: t('patients.title') })
```

## Locale `pt` vs `pt-BR` — Problema de Detecção

O código de locale registrado no app é `'pt-BR'`, mas navegadores enviam `Accept-Language: pt` (sem a subtag `-BR`). Sem mapeamento explícito, o vue-i18n tenta resolver um locale `'pt'` inexistente e emite `WARN [intlify] Not found '...' in 'pt' locale messages`.

**Solução aplicada** — `fallbackLocale: 'pt-BR'` dentro de `detectBrowserLanguage` em `nuxt.config.ts`:

```ts
detectBrowserLanguage: {
  useCookie: true,
  cookieKey: 'i18n_redirected',
  redirectOn: 'root',
  fallbackLocale: 'pt-BR', // mapeia 'pt', 'pt-PT' etc. → 'pt-BR'
},
```

> ⚠️ **Nunca** registre `{ code: 'pt' }` como segundo locale separado — isso duplicaria o português e quebraria a estratégia `prefix_except_default` (a rota `/` ficaria ambígua entre `pt` e `pt-BR`).
